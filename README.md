# چسب طیف ایران (CTI) | chasbteyfiran.com

سایت کاتالوگ سئومحور برای «چسب طیف ایران (CTI)»، تأمین‌کنندهٔ چسب دوطرفه و نوار چسب صنعتی از برندهای tesa، NANO، QUICK TAPE، 3M، Lohmann و NITTO. خرید از طریق تماس، واتساپ و پیام‌رسان‌ها انجام می‌شود (بدون سبد خرید و بدون قیمت؛ قیمت تلفنی اعلام می‌شود).

**تکنولوژی:** Next.js 16 (خروجی کاملاً استاتیک) · Tailwind 4 · shadcn/ui (RTL) · Web Animations API · GSAP + ScrollTrigger (فقط صفحهٔ اصلی) · Lenis · three.js

## دستورات

```bash
npm install
npm run dev      # توسعه روی http://localhost:3000
npm run build    # خروجی استاتیک در پوشه out/
npm run images   # ساخت تصاویر بهینه از assets/client-photos + تصویر OG و آیکون‌ها
```

## کجا چه چیزی را عوض کنم؟

| چه چیزی | فایل |

| نام برند، شعار، تلفن‌ها، واتساپ، ایمیل، آدرس، شبکه‌های اجتماعی، برندها | `src/config/site.ts` |
| لوگو (فایل رنگی CTI؛ از پس‌زمینه جدا می‌شود و آیکون‌ها و تصویر OG از آن ساخته می‌شود) | `assets/brand/cti-logo-color.jpg` و `npm run images` |
| اعتبار طراح در فوتر (فعلاً خاموش) | `developer` در `src/config/site.ts` |
| محصولات (۳۳ محصول: ابعاد، جدول‌های فنی، توضیحات) | `src/data/products.ts` |
| گروه‌های محصول (۱۷ گروه): متن، سؤالات متداول، کلمات کلیدی | `src/data/categories.ts` |
| متن‌های صفحه اصلی، سؤالات متداول، آمار (از روی داده محاسبه می‌شود) | `src/data/home.ts` |
| برش و ساخت تصاویر | `scripts/image-crops.json` و بعد `npm run images` |

اطلاعات محصولات از سه منبع مشتری آمده است: کاتالوگ چاپی NANO / QUICK TAPE (ابعاد، تعداد در کارتن، ویژگی‌ها)، کاتالوگ فنی Qbono (جدول مشخصات و نتایج آزمون) و عکس‌های خود مشتری از رول‌ها و ویترین (نام برند، برچسب‌ها و مقادیر چاپ‌شده روی بسته). مقادیری که در عکس زیر انعکاس نور خوانا نبودند عمداً درج نشده‌اند.

### تصاویر

تصاویر خام در `assets/client-photos/` هستند (عکس‌های کاتالوگ و عکس‌های واقعی رول‌ها و ویترین که مشتری فرستاده است). هر تصویر سایت یک برش از این فایل‌هاست و مختصات برش در `scripts/image-crops.json` ثبت شده. وقتی مشتری عکس واقعی و باکیفیت محصولات را فرستاد، فایل را در همان پوشه بگذارید، `src` و `rect` کلید مربوطه را عوض کنید و `npm run images` را اجرا کنید؛ هیچ کامپوننتی نیاز به تغییر ندارد.

هر تصویر در چند اندازه ساخته می‌شود (۳۶۰، ۴۸۰، ۶۴۰ و ۸۰۰ پیکسل، فقط تا اندازهٔ واقعی خودش) با کیفیت WebP برابر ۸۲، و `sizes` هر تصویر اندازهٔ واقعی نمایشش را می‌گوید؛ پس موبایل فایل ۶۴۰ می‌گیرد، نه ۸۰۰. AVIF هم آزمایش شد و فقط ۱۰ تا ۲۰٪ از WebP کیفیت ۸۲ کوچک‌تر بود؛ برای این سایت ارزش دو برابر شدن فایل‌ها و `<picture>` را نداشت.

نام فایل هر تصویر یک هش محتوا دارد (`name-640.<هش>.webp`). با عوض شدن عکس یا تنظیمات فشرده‌سازی، هش و نام فایل هم عوض می‌شود؛ برای همین مرورگر و گوگل می‌توانند فایل‌ها را یک سال کش کنند و هیچ‌وقت نسخهٔ قدیمی نمی‌بینند.

عکس‌هایی که کوچک‌اند (برش کاتالوگ چاپی) در قاب‌های بزرگ بزرگ نمی‌شوند: `<Picture plate>` آن‌ها را در اندازهٔ واقعی خودشان، روی نسخهٔ محو شدهٔ همان عکس نشان می‌دهد (صفحهٔ محصول، صفحهٔ گروه، درباره ما و کارت بزرگ صفحهٔ اصلی). با جایگزین شدن عکس باکیفیت، این حالت خودبه‌خود غیرفعال می‌شود (عکس‌های ۷۶۰ پیکسل و بزرگ‌تر معمولی نمایش داده می‌شوند).

## انتشار روی هاست

۱. دامنه را تنظیم کنید (برای canonical، sitemap و Open Graph). پیش‌فرض `https://chasbteyfiran.com` است. فقط برای نسخه آزمایشی لازم است عوضش کنید:

```bash
NEXT_PUBLIC_SITE_URL=https://chasbteyfiran.com npm run build
```

۲. **قبل از جایگزینی، از وردپرس فعلی روی هاست بکاپ کامل بگیرید** (فایل‌ها و دیتابیس).
۳. همه محتوای پوشه `out/` (از جمله فایل مخفی `.htaccess`) را در ریشه وب (public_html) آپلود کنید. `.htaccess` ریدایرکت HTTPS، حذف www، صفحه ۴۰۴ سفارشی، فشرده‌سازی و کش را انجام می‌دهد و روی LiteSpeed و Apache کار می‌کند.
۴. فایل `.htaccess`: ریدایرکت یک‌مرحله‌ای به `https://chasbteyfiran.com`، حذف `/index.html`، فشرده‌سازی (gzip) و کش یک‌ساله برای فایل‌های هش‌دار. هدر HSTS عمداً خاموش است؛ بعد از چند روز کار کردن درست HTTPS، علامت `#` اول خط `Strict-Transport-Security` را بردارید. بعد از آپلود با `curl -I -H "Accept-Encoding: gzip" https://chasbteyfiran.com/` چک کنید `content-encoding: gzip` برمی‌گردد.
۴-ب. برای Nginx: `error_page 404 /404.html;` و `try_files $uri $uri/ =404;`
۵. برای نسخه‌های آزمایشی `NEXT_PUBLIC_NOINDEX=true` بگذارید تا گوگل ایندکسشان نکند.
۶. در Google Search Console، دامنه را اضافه و `https://chasbteyfiran.com/sitemap.xml` را ثبت کنید. اگر روش «تگ HTML» را انتخاب کردید، مقدار content را در `NEXT_PUBLIC_GOOGLE_VERIFICATION` بگذارید و دوباره build کنید.

## سئو

- همه صفحات HTML کامل‌اند (بدون نیاز به اجرای JS برای دیدن محتوا)
- یک H1 در هر صفحه، canonical، Open Graph، Twitter Card، `lang="fa-IR"` و `dir="rtl"`
- هر کلمه کلیدی مشتری یک صفحه گروه جدا دارد (`/categories/<slug>/`) و هر محصول یک صفحه (`/products/<slug>/`)
- داده ساختاریافته: `WholesaleStore`، `WebSite`، `ItemPage`، `BreadcrumbList`، `FAQPage`، `ItemList`، `CollectionPage`. صفحهٔ هر محصول `ItemPage` با `about` است، نه `Product`: گوگل برای نتیجهٔ غنی محصول علاوه بر `name` یکی از `offers`، `review` یا `aggregateRating` را می‌خواهد و این کاتالوگ عمداً هیچ‌کدام را ندارد (قیمت تلفنی است و نظر واقعی نداریم؛ ساختگی گذاشتنشان خلاف قوانین گوگل است). `Product` بدون آن‌ها هیچ نتیجهٔ غنی‌ای نمی‌گیرد و در گزارش «Product snippets» سرچ کنسول خطا می‌شود. اگر روزی قیمت یا نظر واقعی داشتیم، `productPageLd` در `src/lib/jsonld.ts` را دوباره به `Product` با `offers` برگردانید (توضیحش بالای همان تابع است).
- `sitemap.xml` (همراه با تصاویر و بدون `lastmod` ساختگی)، `robots.txt`، `manifest.webmanifest`
- عنوان صفحه‌ها حداکثر ۶۵ نویسه است. نام برند فقط وقتی به عنوان اضافه می‌شود که جا داشته باشد (`src/lib/seo.ts`). برای عنوان‌های طولانی‌تر از ۶۵ نویسه، فیلد اختیاری `seoTitle` در `products.ts` و `categories.ts` عنوان کوتاه‌تر می‌دهد، بدون اینکه H1 عوض شود.
- تگ `meta keywords` ندارد (گوگل نادیده‌اش می‌گیرد). اسکیمای `FAQPage` فقط روی صفحهٔ اصلی و صفحه‌های گروه است، چون پرسش‌های گروه در صفحهٔ محصولات هم تکرار می‌شوند.
- تصاویر WebP با `srcset` و ابعاد مشخص (بدون CLS)، فونت وزیرمتن روی سرور خود سایت
- متن فارسیِ مخلوط با اعداد و واحدهای لاتین (مثل `15 N/25mm`) با ایزوله‌های یونیکد (`src/lib/bidi.ts`) درست نمایش داده می‌شود؛ این کاراکترهای نامرئی فقط در متن صفحه‌اند، نه در title و JSON-LD.

## انیمیشن بدون آسیب به سئو

- عنوان صفحه اصلی فقط با CSS انیمیت می‌شود و منتظر جاوااسکریپت نمی‌ماند، پس LCP دیر نمی‌شود.
- انیمیشن‌ها با data attribute در HTML تعریف شده‌اند. بعد از بیکار شدن مرورگر فقط کدی لود می‌شود که همان صفحه لازم دارد (`src/components/motion/motion-root.tsx`):
  - `lite-motion.ts` (حدود ۱٫۴KB، همهٔ صفحه‌ها): محو و بالا آمدن، باز شدن clip، ورود پله‌ای کارت‌ها (`data-reveal`، `data-reveal-group`)، بالا آمدن کلمه‌به‌کلمهٔ عنوان‌ها (`data-split`) و نوار چسب‌ها (`data-tape`)، با Web Animations API و یک IntersectionObserver. زمان‌بندی و easeها همان GSAP قبلی است. عنوان فقط وقتی به دید نزدیک می‌شود شکسته می‌شود، نه موقع لود.
  - `smooth-scroll.ts` (Lenis، حدود ۵٫۶KB): فقط برای ماوس و تاچ‌پد.
  - `gsap-scenes.ts` (GSAP + ScrollTrigger، حدود ۴۴KB): فقط صفحه‌ای که صحنهٔ وابسته به اسکرول دارد (`data-hscroll`، `data-steps`، `data-counter`، `data-draw`، `data-hero-content`، `data-velocity-skew`)، یعنی فقط صفحهٔ اصلی. برای نوشتن انیمیشن ساده در صفحه‌های دیگر از همان `data-reveal` استفاده کنید؛ GSAP را به آن‌ها اضافه نکنید.
- پارالاکس نوارهای بخش آخر (CTA) با انیمیشن اسکرول‌محور CSS انجام می‌شود (`.parallax-root` و `[data-parallax]` در `globals.css`)، بدون JS. مرورگر بدون پشتیبانی نوارها را ثابت نشان می‌دهد.
- فقط محتوای زیر خط دید انیمیت می‌شود، و فقط با transform و opacity.
- متن فارسی فقط کلمه‌به‌کلمه شکسته می‌شود؛ شکستن حرف‌به‌حرف اتصال حروف را خراب می‌کند.
- صحنه سه‌بعدی (three.js، حدود ۱۳۰KB gzip) فقط روی دسکتاپِ عریض با ماوس، WebGL2، حداقل ۴ هسته و ۴GB حافظه لود می‌شود، و فقط بعد از اولین حرکت ماوس یا اسکرول وقتی هیرو در دید است؛ پس بازدیدی که بدون تعامل تمام شود آن را دانلود نمی‌کند. روی تبلت، موبایل، data saver، اینترنت 3G یا کندتر و `prefers-reduced-motion` همان SVG سبک می‌ماند. برای سبک ماندن: وقتی فقط حرکت آرام رول‌هاست ۳۰ فریم در ثانیه می‌کشد و با حرکت ماوس یا اسکرول فریم کامل می‌دهد؛ pixel ratio حداکثر ۱٫۵ و GPU پیش‌فرض (نه high-performance)؛ بیرون از دید و در تب پنهان کاملاً می‌ایستد؛ اگر دستگاه کند بود اول pixel ratio را پایین می‌آورد و اگر باز هم کند بود صحنه را رها می‌کند و SVG می‌ماند. بعد از آمدن صحنه، SVG برداشته می‌شود تا انیمیشن همیشه‌روشنش پردازنده نخورد (`hero-visual.tsx` و `tape-scene.ts`).
- `prefers-reduced-motion` رعایت می‌شود: برای این بازدیدکننده‌ها کد انیمیشن اصلاً دانلود نمی‌شود و پارالاکس CSS هم خاموش است. روی صفحه‌های لمسی Lenis دانلود نمی‌شود؛ DrawSVG هم فقط روی صفحه‌ای که مسیر قابل رسم دارد.
- نوار متحرک (marquee) فقط وقتی در دید است حرکت می‌کند (`marquee-track.tsx`). حلقهٔ همیشه‌روشن ScrollTrigger (داخل خود GSAP است) در کنار یک انیمیشن خارج از دید، روی موبایل متوسط ۹٪ پردازنده را مصرف می‌کرد؛ با این تغییر به حدود ۱٪ رسید. حالا ScrollTrigger فقط روی صفحهٔ اصلی لود می‌شود، پس آن حلقه هم فقط همان‌جا هست.
- **hover آرام و خنثی:** هیچ المانی با hover تکان نمی‌خورد، بزرگ نمی‌شود، نمی‌چرخد و قرمز نمی‌شود. فقط رنگ حاشیه، پس‌زمینه یا یک زیرخط ملایم در ۳۰۰ میلی‌ثانیه عوض می‌شود. دکمهٔ فلش کارت‌ها در `src/components/site/card-arrow.tsx` است.
- **انتقال بین صفحه‌ها:** با View Transitions API مرورگر (`src/components/site/route-transition.tsx` و بلوک «Route transitions» در `globals.css`) صفحهٔ روی صفحه ملایم محو می‌شود. هدر، فوتر و دکمه‌های ثابت جایشان می‌ماند. مرورگرهای بدون پشتیبانی فقط صفحه را عوض می‌کنند. عمداً به خود صفحه نام انتقال داده نشده؛ چون مرورگر باید از کل صفحهٔ ۹۰۰۰ پیکسلی عکس بگیرد و هر کلیک چند ثانیه گیر می‌کرد.

## سرعت: تصمیم‌ها و آزمایش‌ها

- منوی موبایل (Radix Dialog) فقط با اولین hover، لمس یا فوکوس روی دکمهٔ منو لود می‌شود (`mobile-nav.tsx` و `mobile-nav-sheet.tsx`)، و اعتبار طراح هم در chunk جدا است (`developer-credit-lazy.tsx`). حدود ۳۹KB (gzip) از JS اولیه کم شد.
- لوگو در دو اندازهٔ هش‌دار (۱۴۰ و ۲۸۰ پیکسل) ساخته می‌شود و `src/data/brand-manifest.json` را `npm run images` می‌نویسد.
- `<Picture priority preload={false}>` برای عکس بالای صفحه‌ای است که نباید از صفحه‌های دیگر پیش‌بارگیری شود (نکست داده‌های صفحه‌های لینک‌شدهٔ هدر را prefetch می‌کند و React برای هر `<img>` غیرتنبل یک `preload` می‌گذارد؛ یک `<picture>` خالی دور عکس آن را خاموش می‌کند).
- نوار گوشهٔ چسب (`.has-tape::before`) و فلش دکمه‌های گرد (`.card-arrow::after`) با CSS کشیده می‌شوند، نه با المان اضافه، تا DOM کوچک‌تر شود.
- آزمایش و ردشده: `experimental.inlineCss` در `next.config.ts`. CSS دوبار داخل HTML می‌آید (یک‌بار در `<style>` و یک‌بار در دادهٔ RSC) و HTML هر صفحه حدود ۴۵KB (gzip) بزرگ‌تر می‌شد، بی‌آنکه LCP یا امتیاز لایت‌هاوس بهتر شود. CSS فعلی بیشتر خودِ کلاس‌های استفاده‌شده است (۸۳KB خام، ۱۵KB gzip).
- هشدار «Legacy JavaScript» لایت‌هاوس مربوط به یک ماژول ۱٫۴KB داخل خود Next است (`polyfill-module`)؛ browserslist پیش‌فرض Next از قبل مدرن است و با تنظیمات حذف نمی‌شود.
- **JS بی‌مصرف حذف‌شده:**
  - صفحه‌هایی که فقط انیمیشن ساده دارند دیگر GSAP، ScrollTrigger و SplitText دانلود نمی‌کنند (حدود ۴۷KB gzip کمتر؛ بالا). SplitText دیگر هیچ‌جا لازم نیست.
  - در کامپوننت‌های سمت‌کلاینت از `cx` (`src/lib/cx.ts`) استفاده کنید، نه `cn`. `cn` شامل tailwind-merge است (حدود ۱۰KB) و یک import در یک کامپوننت `"use client"` آن را روی همهٔ صفحه‌ها می‌فرستاد. `cn` را فقط در کامپوننت‌های سرور یا جایی نگه دارید که واقعاً باید کلاس‌های متعارض ادغام شوند (مثل `Sheet` و `Button`).
  - دادهٔ کامل گروه‌ها (توضیح و سؤال‌ها، حدود ۶KB) دیگر داخل کد منوی موبایل نمی‌رود؛ هدر فقط `slug` و `name` را می‌دهد (`header.tsx`). `table.tsx` دیگر `"use client"` ندارد. وابستگی بی‌مصرف `@gsap/react` حذف شد.
  - بعد از این تغییرها JS اولیهٔ هر صفحه حدود ۱۲KB کمتر است و هر صفحهٔ غیر از خانه حدود ۵۵KB کمتر JS دانلود می‌کند (۱۵۰KB به‌جای ۲۰۵KB روی دسکتاپ). آنچه می‌ماند تقریباً همه React و runtime خود Next است (حدود ۱۳۰KB).
- Next روی ۱۶٫۴٫۶ (آخرین نسخهٔ پایدار) است. این ارتقا یک وصله بود و اندازهٔ باندل‌ها را تغییر نداد.
- برای دیدن اینکه چه چیزی در JS است: موقتاً `productionBrowserSourceMaps: true` را در `next.config.ts` بگذارید، build بگیرید و بایت هر chunk را با source map به پکیج و فایل نسبت دهید (مثل source-map-explorer). بعد تنظیم را بردارید تا فایل‌های `.map` در `out/` نماند.
- **صفحه‌بندی صفحهٔ محصولات آزمایش و رد شد.** این صفحه ۸۹۹ عنصر دارد (۳۳ کارت × ۱۳ عنصر، حدود نیمی از آن). با صفحه‌بندی ۱۲ محصولی حدود ۶۲۶ می‌شد، ولی روی شبیه‌سازی گوشی ۴ برابر کندتر فقط حدود ۴۰ میلی‌ثانیه style و layout و paint کم می‌کرد، TBT همین صفحه ۵ms است و امتیاز لایت‌هاوس تقریباً تغییری نمی‌کرد. در عوض صفحهٔ «همهٔ محصولات» که بر پایهٔ گروه چیده شده و چیپ‌های لنگر دارد به چند URL تقسیم می‌شد و لینک هر ۳۳ محصول دیگر از یک صفحه به گوگل نمی‌رسید. اگر تعداد محصولات چند برابر شد، دوباره بررسی شود.
- فرضیهٔ «`text-wrap: pretty` و `balance` لایه‌بندی را کند می‌کنند» هم سنجیده شد: حذف‌شان در خانه فقط ۱۰ تا ۳۰ میلی‌ثانیه از style و layout کم می‌کرد (در حد نوسان اندازه‌گیری، روی شبیه‌سازی ۴ برابر کندتر)، پس عوض نشد.

## فونت

وزیرمتن تحت مجوز SIL Open Font License.

فونت با `display: optional` و preload لود می‌شود (`src/app/layout.tsx`): اگر در حدود ۱۰۰ میلی‌ثانیهٔ اول برسد (اینترنت خوب یا فونت کش‌شده) استفاده می‌شود؛ در غیر این‌صورت همان بازدید با فونت سیستم می‌ماند و وسط کار عوض نمی‌شود، پس چینش صفحه جابه‌جا نمی‌شود (CLS ناشی از فونت صفر است). فونت در پس‌زمینه دانلود و یک سال کش می‌شود و از بازدید بعد همیشه استفاده می‌شود. اگر ظاهر دقیق فونت در اولین بازدید مهم‌تر بود، `display` را به `"swap"` برگردانید.
